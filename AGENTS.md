# Agent Instructions

- Always check the `specs/` folder before making changes.
- Treat specs as project requirements.
- Never update files in `specs/` without asking the user first and receiving explicit approval.
- If a spec appears outdated or needs to change, propose the exact spec update to the user before editing it.
- If a requested change or planned implementation conflicts with anything written in a spec, ask the user for explicit confirmation before proceeding.
- Never use tool names in branch names. Do not use prefixes like `codex/` or `claude/`; use task- or feature-focused branch names instead.
